# Trusted protocol preview implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the raw recommendation-engine dump with a trustworthy, plain-language pre-start protocol preview that explains the route, owned items, timing, evidence, limitations, and eligible alternatives without changing the stored decision.

**Architecture:** Keep `ProtocolDecision` immutable as the audit and execution record. Build a separate deterministic, fail-closed `ProtocolPreviewModel` from the exact decision, its stored `RecommendationContext`, and the exact checked-in reviewed-content registry version. Render only that allowlisted model; never render or regex-scrub engine prose, rule references, fact paths, UUIDs, reviewer identities, URLs, or internal capability keys.

**Tech stack:** TypeScript, React Native, Zod, Vitest, React test renderer, Expo SDK 57.

**Spec:** `docs/superpowers/specs/2026-10-10-canonical-product-spec.md`; `docs/superpowers/specs/2026-10-10-product-recovery-audit.md`

## Global constraints

- Use Node 24.19.x; the machine default Node 25 is unsupported.
- Write a genuine failing test before each implementation change and retain RED/GREEN evidence.
- Require at least 80% statements, branches, functions, and lines for every new or materially changed logic file.
- Preserve the original trusted `ProtocolDecision` for persistence, replay, and execution.
- Draft, withdrawn, malformed, mismatched, or unscoped content returns `content_pending`; it cannot produce a preview, run, or Start action.
- Do not publish Banana content or invent rules, capabilities, evidence, reviewer identities, products, tools, or recommendations.
- Do not expose raw rule references, fact paths, UUIDs, evidence IDs, reviewer names, URLs, SQL codes, or engine prose to visible or accessibility text.
- No Cue Check, photos, OCR, weather, Routine Audit, reminders, diagnosis, hosted changes, migration, push, merge, deploy, or Task 3.4 work.

## Review focus

- A stored plan whose product or tool version no longer resolves must fail closed rather than name a different item.
- A restored plan must use its stored context and exact reviewed-content version, never current mutable Shelf, Tools, or Passport data.
- An unknown action, capability, evidence reference, or registry version must produce conservative unavailable copy and no Start action.
- A rejected or hard-fail candidate must never appear as an alternative.
- Owner switching, stale async generation, retry, large text, and TalkBack focus must never paint or announce the previous owner's preview.
