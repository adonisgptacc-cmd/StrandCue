# Privacy matrix — personal-data categories vs migrated behavior (2026-10-15, HEAD `57042f9`)

Scope: every row is grounded in the migration chain at HEAD, the two runbooks
(`docs/runbooks/privacy-retention.md`, `docs/runbooks/account-deletion.md`),
and the Task 9–13 test suites. No invented policy: anything not enforced in
code is marked as such. Product intent lines (P1-PRIV-01/02/03 in
`docs/PHASE_1.md`) state purpose; the migrations state mechanism.

Why a new file: no existing verification file tabulates all personal-data
categories against collection, purpose, export, deletion, retention, and
owner authorization in one place. `docs/verification/security-hardening-2026-10-04.md`
maps audit finding IDs; the runbooks give operator steps per category; the
export tripwire test pins the table registry in code. This matrix is the
reader-facing join across those three.

Conventions: "export v2" = the `schemaVersions` block introduced by
`20261015181916_export_complete.sql` (`export: 2, consentRecords: 1,
recommendationRuns: 1, protocolExecutions: 1 → 2 after Task 13,
protocolExecutionEvents: 1`); absence of the block (JSON) or of
`schema_versions.csv` (CSV) identifies a pre-expansion export whose missing
sections are *unknown, not empty*. Every owner predicate below keys off
`strandcue_private.request_uid()` (the JWT `sub` claim); every touched table
has RLS enabled **and forced** with mutator-only writes unless noted.

Cross-cutting notes (all code-grounded):

- The export tripwire test (`tests/database/export.test.ts`) pins the registry: 21 exported + 14 excluded = 35 owner tables (23 public + 12 `strandcue_private`), plus the exact per-table column registry — any new owner table or new column on an exported table fails until classified. The matrix above is the prose mirror of that registry.
- `strandcue_private.*` operation ledgers (idempotency payloads) and `username_operations`/`username_option_limits` are service-internal rate-limit/idempotency state: OUT of export, cascade on purge, mutator-only, owner-scoped.
- Nothing in this matrix authorizes hosted application: purge scheduling, Auth Admin deletion, and the dashboard toggle are pending operator/hosted steps (see handoff obligations).
